# Commands

Implemented commands. [Engineering §1](../specs/06-engineering-delivery-and-operations-spec.md#1-bootstrap-and-command-scope) points to this list, and [engineering §7](../specs/06-engineering-delivery-and-operations-spec.md#7-application-command-contract) defines the commands that are still required.

| Command | Behaviour |
| --- | --- |
| `pnpm verify` | Run repository checks and their regression tests; Rust format, clippy, tests, the build of `engine-batch`, the S0 offline replay and the contracts report; then check the installed dependencies against `pnpm-lock.yaml`, run the workspace checks (including the Turborepo task list of every workspace package and a Cargo test target for every tracked integration test file), Turborepo typecheck, lint, test and build without cached results, and the workspace tests. The Vitest package tests and the workspace `node:test` tests fail a run that executes no test, or skips or filters out a test. The Rust tests (`cargo test`) and the repository regression tests are not covered by that rule: an `#[ignore]` Rust test or a skipped repository test does not fail verification. Each step runs without inherited variables that could switch it off, such as `NODE_OPTIONS`, `RUSTFLAGS`, a Cargo test runner or a `pnpm_config_*` setting. The `@openquant/api` tests run against a real PostgreSQL 14 or later: they use the server named by `OPENQUANT_TEST_DATABASE_URL`, or start a temporary cluster from the server binaries on the machine, and fail with instructions when they have neither. Among them, `apps/api/test/e2e.connected.test.ts` runs the connected path end to end with the `engine-batch` debug binary and the `local-runs/s0` index that the Rust steps wrote before, and `openssl` for its loopback certificates; it fails with the command to run when one is missing (below). Needs Node 24 and `pnpm install --frozen-lockfile` first; it never installs. |
| `pnpm verify:repository` | Run the repository integrity checks only, including the static verification guards and the static checks of the infrastructure files (`scripts/infrastructure.ts`: the environment profile, the Fly profiles, the Dockerfiles and `.dockerignore`, and the Terraform pins, backend and Hyperdrive caching). They do not run `terraform validate`, flyctl or Docker. CI runs them as their own step before any install. |
| `pnpm verify:contracts` | Run the TypeScript and Rust contract parity test. It needs `local-runs/contracts/report.json` from the Rust contracts report and fails without it, or when the test does not run. |
| `pnpm test` | Run the regression tests of the repository checks. |
| `pnpm --filter @openquant/api run migrate` | Apply the pending SQL migrations of `apps/api/migrations`, in order, to the database that `DATABASE_URL` names (a direct connection string, not a pooled one), each file in its own transaction under one advisory lock, and print the applied ids and the migration level. With `-- --status` it prints what is applied and pending and changes nothing. It refuses a changed or missing applied file, and it never prints the connection string. |
| `pnpm --filter @openquant/api run bootstrap -- --environment <DEVELOPMENT\|STAGING\|PRODUCTION> --out <file>` | Create the first Administrator and the `batch`, `runner`, `workflows` and `deploy` service principals of an environment on a clean database (`DATABASE_URL`, a direct connection string), with one credential each, in one transaction. It writes the credentials, shown once, to the new file that `--out` names, created with mode 0600 and never overwritten, and prints only the identifiers and the path. The database stores only hashes. It refuses an environment that has principals already, and a failure removes the file and creates nothing. The file belongs in a secret store, never in Git. Options `--admin-id` and `--admin-name` name the Administrator. |
| `cargo run --locked -p openquant-engine --bin s0-replay` | Replay the S0 fixture cases and write `local-runs/s0/report.md`. |
| `cargo build --locked -p openquant-engine --bin engine-batch` | Build the batch host binary (the one HTTP client of the connected engine). `pnpm verify` runs it, so a binary that does not build fails verification even when no test starts it. |
| `cargo run --locked -p openquant-engine --bin engine-batch -- --check-config` | Read the batch host configuration from the environment (`OPENQUANT_ENVIRONMENT`, `OPENQUANT_API_URL`, `OPENQUANT_API_TOKEN`, `OPENQUANT_QUEUE_ACCOUNT_ID`, `OPENQUANT_QUEUE_ID`, `OPENQUANT_QUEUE_TOKEN` and the optional variables of the [engine README](../../apps/engine/README.md#configuration)), print `configuration ok` and exit. It fails closed with exit status 2 and names the first missing or invalid variable, never a value. It makes no request. |
| `cargo run --locked -p openquant-engine --bin engine-batch` | Run the batch worker: pull job messages from one Cloudflare queue over HTTP, claim each attempt through the application API, run the `retrieve`, `validate`, `evaluate` or `assess` job and acknowledge the message after the result is committed. Exit 0 after a stop request (`OPENQUANT_STOP_FILE`), 1 when a credential is refused, 2 for a usage or configuration error. It needs the API, the queue and the credentials named above, which do not exist in this repository: only its tests run it, against fakes. A debug build also accepts the test-only `OPENQUANT_TEST_LOOPBACK_PORT` and `OPENQUANT_TEST_LOOPBACK_ROOT` in `DEVELOPMENT`: the allowlisted hosts then resolve to that loopback port and the wire trusts only that certificate authority. A release build, or any other environment, refuses to start with either set. Provider retrieval stays off unless `OPENQUANT_MARKET_RETRIEVAL` is exactly `enabled` and the recorded probe evidence verifies six facts. |
| `pnpm --filter @openquant/api exec vitest run test/e2e.connected.test.ts` | Run the S1 connected test alone, after `pnpm exec turbo run build --filter=@openquant/api^...`: the real API on PostgreSQL, the built `engine-batch` binary in its test-only loopback mode, the agent runner's modules with a fake executor, and loopback fakes of the Cloudflare queue and Alpaca. It drives one pilot-shaped mission through the api-client to `CONCLUDED` with `NO_ELIGIBLE_CANDIDATE`, checks candidate cash isolation, replays every S0 case through `start_replay` (Administrator only, its own replay budget) against the `s0-replay` digests, fails the semantic-invalid seeds explicitly and resumes a killed evaluation from its checkpoint journal. It needs `target/debug/engine-batch`, `local-runs/s0` and `openssl`, fails with the command to run when one is missing and never skips. No credential, provider, model or network call is used. The [M1 guide](../guides/m1-watchlist-research.md#run-the-s1-connected-test-locally) gives the steps. |
| `docker build --file apps/engine/Dockerfile --tag openquant-engine-batch .` | Build the `engine-batch` image from the repository root: a locked release build on the pinned Rust toolchain, on base images pinned by digest, running as a non-root user. The build runs the binary with `--check-config` and fails unless it reads a synthetic configuration and refuses the test-only loopback variables. It fetches only the crates of `Cargo.lock` and the base images. It has not been built yet: there is no Docker daemon in the development container and no CI job builds it (planned for P6.2). |
| `docker build --file apps/agent-runner/Dockerfile --tag openquant-agent-runner .` | Build the agent-runner image from the repository root: the runner built from the locked workspace (no install script runs), Claude Code at the pinned executor version (only its own install script runs), Node 24 pinned by digest, the `node` user, no credential. The build fails unless `claude --version` names the pinned version; it never runs the executor with a prompt. It has not been built yet (as above). |
| `cargo run --locked -p openquant-contracts --bin contracts-report -- --out local-runs/contracts` | Write the Rust contract-layer verdict, code and digest of every protocol fixture to `local-runs/contracts/report.json`. |
| `pnpm --filter @openquant/agents run eval:fixture` | Run every offline agent fixture in `fixtures/agent-results` through request assembly and result parsing and print one line per case. Fixture mode only: it calls no model and refuses `--mode live`. Needs `pnpm install --frozen-lockfile` first. |
| `pnpm agents:eval` | Evaluate the proposer and critic modules with real models (OQ-06 §7). Without `--mode` it refuses, exits 2, names `--mode live`, `--allow-real-model-calls` and the missing key, and calls no model. `--mode fixture` runs every offline fixture of `fixtures/agent-results` and says that no model was called. `--mode live` makes real, billed model calls through the production runner path (the pinned executor and the shipped behaviour bundle) and writes a report with the actual model, validity, known-flaw detection, cost and latency of each trial. It refuses, calls no model and starts no process unless all of these hold: `--allow-real-model-calls`, `--max-budget-usd` covering every attempt at its reservation, the key of the owner in `OPENQUANT_EVAL_ANTHROPIC_API_KEY` (never a credential of the running session), the absolute path and pinned version of the executor in `OPENQUANT_EVAL_EXECUTOR_PATH` and `OPENQUANT_EVAL_EXECUTOR_VERSION`, and no coding-agent session (`CLAUDECODE`, `CLAUDE_CODE_*` and `CCR_*` unset). Proxy and certificate variables reach the executor only with `--allow-proxy-env`. Live mode has never been run: no key exists in this repository or its sessions. Needs `pnpm install --frozen-lockfile` first. |
| `pnpm --filter @openquant/agents run bundle:update` | Rewrite `packages/agents/bundle.manifest.json` from the shipped files and the derived result schemas. The bundle hash is the SHA-256 of the manifest bytes, so review the change; the package build fails while the manifest and the files differ. |
| `pnpm --filter @openquant/agent-runner run test` | Run the tests of the agent runner: fake executors, loopback API and dispatch servers, and the built runner as a program. They use no network, no credential and no model. Needs `pnpm install --frozen-lockfile` first. |
| `pnpm --filter @openquant/agent-runner run build` | Type check the runner and bundle `src/main.ts` into `apps/agent-runner/dist/agent-runner.mjs` for Node 24, with the behaviour bundle in `apps/agent-runner/dist/bundle`. Fails on a dependency other than a Node built-in, or on a bundle file that differs from `packages/agents/bundle.manifest.json`. |
| `node apps/agent-runner/dist/agent-runner.mjs` | Start the agent runner (also `pnpm --filter @openquant/agent-runner run start`) after a build. It reads `AGENT_RUNNER_*` variables (see the runner README), serves `POST /v1/agent-attempts`, refuses to start on an invalid configuration, and keeps execution off unless `AGENT_RUNNER_ENABLED=true`. It needs a control API and, to run an executor, the pinned CLI and a model credential: nothing in the repository supplies them. |
| `pnpm --filter @openquant/api-client run test` | Run the tests of the typed API client against a fake API: client command IDs, the read-back of `PENDING` and `UNKNOWN` outcomes, resynchronisation after `REVISION_CONFLICT`, the typed errors of `api-error/1` and the validation of every answer. `pnpm --filter @openquant/api run test` runs the client against the real API on PostgreSQL. Needs `pnpm install --frozen-lockfile` first. |
| `pnpm --filter @openquant/cli run build` | Type check the CLI and bundle `src/main.ts`, with Ink and React, into `apps/cli/dist/openquant.mjs` for Node 24. Fails when the bundle would load anything but a Node built-in module. |
| `node apps/cli/dist/openquant.mjs <command> [--json]` | Run the operator CLI after a build. The [CLI reference](cli.md) gives every command, its role, its output and its exit code. Each result carries the environment, the mode (`BACKTEST`), the simulated per-candidate ledger and risk `UNKNOWN` with its reason; `--json` prints one JSON document and renders nothing. No API is deployed, so it has run only against the API test app and loopback fakes. |
| `openquant login [--api <url>]` | Read a person's credential from stdin (hidden prompt in a terminal), exchange it for a 15-minute access token, read the environment, and store both in `credentials.json` (mode 0600) in `OPENQUANT_CONFIG_DIR`, `$XDG_CONFIG_HOME/openquant` or `~/.config/openquant`. Prints neither. https only, except for localhost. `openquant logout` removes the file. |
| `openquant budget register`, `profile register`, `policy register --file <path>` | Steward: send `register_budget`, `register_research_profile` or `register_cohort_policy` with a client command ID and read the outcome back. A Researcher or a Viewer is refused (exit 4). |
| `openquant seed register --file <path>`, `openquant mission create --file <path>` | Researcher: send `register_seed` or `create_mission`; a created mission is read back and shown. |
| `openquant mission run-now <id>`, `openquant mission cancel <id> --reason <text>` | Researcher: read the mission, ask for an explicit confirmation in a terminal (`--yes` elsewhere), and send the command with the revision shown. A stale revision exits 7 with the mission read again; a lost answer exits 9 and is kept for `openquant command resolve <id>`. |
| `openquant mission show`, `budget`, `lineage`, `trials`, `findings`, `gates`, `decisions <id>` | Read one view of a mission and print it within 80 columns. `decisions` shows `none recorded` only for the `EVALUATING` → `PAPER` Decision. The first read of holdout observations through `gates` is recorded as their consumption. |
| `openquant mission results <id> [--candidate <trial-slot>]` | Show the official values of each candidate's runs from `runs.metrics` and `runs.result`: D, V and H side by side for the base and cost-stress cases, both benchmarks, the simulated per-candidate ledger, the window label from the evaluation plan and the uncertainty statement. Nothing is recomputed; a value not committed yet is `unknown`. Reading a holdout run's values is recorded as holdout consumption. `--json` returns the committed documents unchanged. |
| `openquant mission watch <id> [--interval <s>]` | In a terminal only: show the mission, read again every 5 to 300 seconds, marked `STALE` with its read time after a failed read. `q` detaches without cancelling. |
| `openquant command show <id>`, `openquant command resolve <id>` | Read a command back by its ID; settle a command whose outcome is `UNKNOWN`, or whose process was interrupted, by reading it back and, only if the API has none with that ID, sending the identical request once more. Every command is journalled with its API and principal before it is sent; `resolve` refuses (exit 13, nothing sent) under another API or principal. |
| `pnpm generate:spec-index` | Generate the ownership/version index from the seven front-matter blocks. |
| `pnpm generate:tree` | Generate the file map from the Git index, or files in an extracted archive. |

Each `pnpm` command runs the script named in root `package.json`, under the settings of `pnpm-workspace.yaml`. A change to either file can therefore change what `pnpm verify` runs; check such a change with `node scripts/verify.ts`. Each S1 pull request that implements a command adds its row here, in the same change as the command's implementation and tests. Do not add a row for a planned command.
