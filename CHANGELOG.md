# Changelog

## Unreleased — bootstrap

- Consolidate seven canonical specifications under `docs/specs`.
- Preserve Design v2 acceptance A01–A18 and repository acceptance R01–R10.
- Retain Cloudflare orchestration and Fly.io native execution.
- Add source ownership guides, contributor policies, issue/PR templates, and CI.
- Add TypeScript checks for metadata, file-map drift, links, source hashes, and workflow conventions.
- Archive nine supplied design references with SHA-256 provenance.

- Add the S0 offline seed evaluation: a Cargo workspace with a pinned toolchain, versioned input/result/checkpoint schemas with generated Rust bindings and runtime validation, a shared Rust core (typed operator interpreter, daily execution phases, exact accounting, corporate actions, checkpoint restore), four versioned seed Strategy Definitions, independent synthetic fixtures, a local replay report, and Rust checks in `pnpm verify` and CI.
- Decide every S0 level comparison (stop and target touch, gap, validity, break-even trigger, entry signal) on exact rational values, and keep levels exact through splits. A level that does not fit 128 bits, or has no decimal view (an integer part of 2^96 or more), fails with `ARITHMETIC_OVERFLOW` at the event that creates it. The checkpoint may carry a level as a reduced fraction `n/d` (`Exact`). Add 25 independent grid-tie cases (G-01 to G-13b) and three cases for levels without a decimal view (I-12a to I-12c).
- Add the S1 TypeScript workspace (pnpm, Turborepo, strict TypeScript, Biome, Vitest) and `@openquant/api-contracts`: generated types and standalone validators for every shared schema, strict JSON, canonical SHA-256 digests and the Rust contract-layer order, with a parity test against the Rust contracts report.
- Add the S1 TypeScript steps to `pnpm verify` and CI: the Rust contracts report, a dependency check against `pnpm-lock.yaml` that never installs, Turborepo typecheck, lint, test and build without cached results, and workspace checks for licences, import boundaries and parsed workflow YAML.
- Close the verification guard gaps of the P1 review: CI checks fix every step, input and environment variable of the `checks` job; `verify.ts`, its step environment and the step runners must equal their reviewed code; every step runs without inherited variables that could switch it off; the workspace packages, their task scripts and the Turborepo task list are literal; Vitest and `node:test` reporters fail a run that executes no test or skips one; tracked Cargo configuration and manifest settings that skip tests fail.
- Close the second-round verification guard gaps of the P1 review: `pnpm-workspace.yaml` may set only `packages`, `verifyDepsBeforeRun: error` and the reviewed `allowBuilds`, and no other tracked file configures pnpm; the root scripts are a literal set, no manifest defines an install lifecycle script or hook, and CI installs with `--ignore-scripts`; CI runs the repository checks as their own step before any install; the top-level code of the guard modules may not use `process`, the environment or an exit, and no verification script reads the `CI`, `GITHUB_*` or `RUNNER_*` variables; Cargo manifests are read as TOML, and the workspace checks require a Cargo test target for every tracked integration test file; the `node:test` reporter compares the files that ran with the listed workspace test files; a Dependabot update of a pinned action commit passes. The guards run inside the code they guard, so changes to `scripts/**` and `.github/**` rely on code-owner review.
- Require a `# v<major>.<minor>.<patch>` comment at the end of every action reference in the workflows; the guards check its form only, not that it names the release of the pinned SHA, which code-owner review of `.github/**` covers. State that a change to the root `package.json` scripts or to `pnpm-workspace.yaml` is caught by `node scripts/verify.ts` and the CI `Check repository` step, not reliably by `pnpm verify`.
- Close the verification guard gaps of the full P1 review: every `NPM_CONFIG_*` and `PNPM_CONFIG_*` variable, `RUSTDOC` and `CARGO_BUILD_RUSTDOC` are removed from the environment of every step, because pnpm turns `pnpm_config_node_options` into the `NODE_OPTIONS` of `pnpm exec node` and Cargo runs doc tests through `RUSTDOC`; `scripts/workspace/check-workspace.ts` is pinned by SHA-256, so a deleted guard call or an exit status of 0 fails the repository checks; the no-skip rule is stated for the Vitest and workspace `node:test` tests only, and the Rust tests and the repository regression tests are recorded as not covered; the test task of `@openquant/api-contracts` lists `packages/quant-core/tests/result_size_bound.rs` as an input; `AGENTS.md` gives the real order of the TypeScript steps.
- Add the durable API foundation of S1 (`apps/api`, `@openquant/api`): a Hono app built from the route manifest, with the route layer (body limit before parse, `api-error/1` mapping, roles and credentials per route), app-issued tokens (15-minute access tokens, service credentials scoped to operations, attempt capabilities that expire with the lease), `auth.token`, `system.identity` and `/health`, seven SQL migrations with a runner and the specification's state rules as constraints, and tests on a real PostgreSQL server that `pnpm verify` provisions itself. The other routes answer `UNAVAILABLE` and name the part that builds them. The Worker runtime (workerd, Hyperdrive, R2) is not tested here.
- Add the guarded commands and the state machine of the durable API (`apps/api`): the nine commands of `command/1` with client command IDs, idempotent replay, recorded refusals and status read-back (`commands.show`); the transition table of OQ-05 §4 as guarded functions with compare-and-set revisions, fencing by ownership revision and lease, retry classes with the attempt cap, retries that wait for budget with the mission `BLOCKED`, and cancellation; budgets with a reservation before dispatch, settlement that never returns more than the reservation, overruns and unknown usage kept reserved; the policy-determined `DRAFT` to `EVALUATING` Decision and `freeze_candidates` for the workflows service principal, each writing its runs, reservations and outbox entries in one transaction; finding treatment and holdout consumption. Research execution is off by default (`OPENQUANT_RESEARCH_EXECUTION`). Tests on a real PostgreSQL inject a failure after every write of each command and race a cancellation against a completion.
- Complete the routes of the durable API (`apps/api`): the claim of an attempt with a lease and an attempt-scoped capability, content-addressed inputs and artefacts, and the five result submissions (retrieval, validation, evaluation, gate report, agent result) that commit a result only from the current owner and only when every hash binds, with the 8 MiB result scan, the outcome mapping of OQ-02 §3.6, one official result per run and late or repeated submissions rejected or answered from the stored one; the evaluation plan recorded with the accepted retrieval; the outbox dispatcher and a scheduled recovery pass (expired leases fenced up to the attempt cap, terminations confirmed before anything is released, pending dispatches sent) over interfaces for the batch queue and the agent runner; the read models of every GET route; `releases.record`; and a bootstrap command for the first Administrator and the service principals. No route answers "not implemented" any more. Tests on a real PostgreSQL cover the permission matrix of every route, redelivery, a worker that dies at every attempt, cancellation against completion and the audit record of every refusal. The Workflows (P5), the batch host and agent runner calls, and the Worker runtime are not covered.

- Add the S1 market-data library to `apps/engine` (`market` module): the Alpaca adapter over an HTTP transport seam (raw daily and minute bars, corporate actions, calendar, asset record; pagination, `Retry-After`, typed errors, a request budget enforced outside the adapter, credentials never printed), a normaliser that writes `dataset-manifest/1` with per-bar and per-action availability under the profile's rules (blocking the profile where the declaration date does not precede the ex-date), the provider enablement gate (off by default), the session probe comparison and the retrieval sequence, with 47 synthetic Alpaca-shaped cases and an independent oracle under `fixtures/market-data`. No provider is called: the endpoint shapes are unverified and the real transport, queue and batch host are not implemented.

No trading application, connected research, broker adapter, model runner, cloud deployment, or package release is implemented.
